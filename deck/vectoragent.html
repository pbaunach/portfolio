02Problem

Agents draw their own icons, and it goes badly

d="M2.5 4h2.6l2.3 11h19…"✕ path escapes viewBox

The drawing comes out wrong

Ask a coding agent (Cursor, v0, Devin) for a cart icon and it writes the SVG from memory, picking coordinates in plain text. Paths break and shapes spill outside the viewBox.

~300

It burns tokens to get there

Eighty lines of XML per icon, roughly 300 output tokens. That slows the build down and crowds out the context window.

The fallback is scraping a CDN, which hands a commercial codebase artwork nobody can prove the rights to.

03Solution

Let the agent buy the icon instead of drawing it

An M2M marketplace, not an asset store

Stores today sell a $15–$50 pack of 500 icons to a person, ahead of time. An agent wants one icon, mid-build, and will never open a zip.

The paying happens inside the call

No signup, no API key, no checkout. The tool meets the 402, signs, and retries on its own. The agent only ever sees a tool result.

The creator gets paid per use

Every fetch is a real transfer on a public ledger, so what an icon earned is a matter of record, not a monthly estimate.

04Matching

Picking the right one is the hard part

Three, not a hundred

Tags, visual embeddings, and which icons agents actually kept weigh the list down. The other ninety-seven never touch the context window.

Looking is free, taking is not

Search returns watermarked, low-resolution previews at no charge. Payment happens only on the fetch.

What lands already fits

The pick binds the session to that set, so later calls match it, and a miss falls back to the nearest visual match. The file carries currentColor, so it takes the styling around it too. No cleanup pass.

05Why Now

Two standards landed at the same time

Standard 1 · Tools

Anthropic's MCP

Model Context Protocol is how LLMs reach outside tools now. Agents already know how to call a tool server. Nobody has to teach them.

> tools/call fetch_vector_icon

+

Standard 2 · Payments

Linux Foundation's x402

HTTP 402, "Payment Required," finally has a spec behind it. An agent can settle a sub-cent payment in the request header and move on.

Backed by
CoinbaseStripeCircleStellar

We built it. The whole loop runs today.

    |                                                                |

    |                                                                |
    |--- 3  retry + signed Soroban transfer ------------------------>|   agent wallet signs
    |                                                                |
    |<---    200 OK  ·  <svg/> returned -----------------------------|   once the ledger clears
    |                                                                |

A real 402

Not a mock. An unpaid request never reaches the icon.

A real transfer

The agent wallet signs a USDC transfer; a hosted facilitator broadcasts it.

Checked against the ledger

Confirmed on Horizon, not in our own logs. Balances moved, then the SVG came back.

Not yetFive hardcoded icons, no search, no creator payouts, testnet only. Proving the payment loop was the whole point.

07Business Model

Agents pay per asset. Most of it goes to whoever drew it.

Tier 1Free

A free baseline

$0.000 per asset

Solves the cold start. An agent that calls the tool always gets something back. How big the set is, and what goes in it, is still open.

Tier 2On demand

Paid designer sets

$0.002 – $0.010 per asset

Niche, brand-specific, or indemnified artwork, bought one icon at a time.
